Q2JUMP Starter 0.4.0: game data, Q2PRO Race and R1Q2 Race

Choose the game folder in Setup; the editable default is C:\Q2JUMP.
For an existing game, select the root folder containing baseq2\*.pak, not a
new Q2JUMP folder inside it. The folder picker uses exactly the folder chosen.
Selecting an existing folder is expected; Setup validates it before continuing.
The folder page gives read-only feedback as you type or browse, including PAK
presence and client files found. This does not verify their contents or replace
the full destination checks before copying.
Space information shows the game-data size and temporary-space requirement
separately; client and backup space depends on the selected releases and existing
files and is checked before client files change.
Choose "Install a new game" for an empty folder. Starter downloads the pinned
original demo and official 3.20 update archives, then selects the original
data and required notices. A Starter-owned folder can be retried after an
interruption. Choose "Install or update clients in an existing Quake II
folder" to reuse a .pak file in baseq2 without downloading original
data. Starter does not open, decode, hash or validate existing PAK contents.
Downloaded archives are hash-verified before extraction; original installers
are never executed. Original game data is not bundled in Setup.

Choose Q2PRO Race, R1Q2 Race, or both. Starter downloads the current Windows x64
packages from the latest GitHub releases in MovoWR/q2pro_race and
MovoWR/r1q2_race respectively. A temporary helper verifies each HTTPS download,
archive checksum, executable architecture and managed-file inventory. Q2PRO
versions use r<number>; R1Q2 versions are displayed as <number> ups. R1Q2
packages named either r<number>.zip or <number>ups.zip are accepted.

Client executables and jump resources are installed into the selected game
folder. Fresh installations keep notices in .starter/licenses, source references
in .starter/source, and client records, recovery files and configuration backups
in .starter/q2pro and .starter/r1q2. The game root contains .starter, baseq2, jump
and the selected client executables, plus any required runtime DLLs.
Existing installations retain their original .q2jump, .q2jump-r1q2, licenses and
source locations. Both layouts support updates and recovery; this version does
not move existing folders. Unknown or mixed metadata layouts are rejected.
Q2PRO's jump/q2config.cfg and R1Q2's
jump/config.cfg are preserved. Shared managed files must have identical bytes
in both client releases. Conflicts stop the update before replacement; use
separate folders for incompatible releases. Both clients are installed in
order, Q2PRO then R1Q2. If the second fails, the first remains installed.

Client progress and file-change reviews stay inside the Setup window. Downloads
show percentage and MiB. Staging, backups and file installation show completed-file
counts and progress for the current stage; final verification is identified
separately. Review each requested change and choose Install / Update to approve
it. Cancel, Escape or
closing the window requests a safe stop and waits for the helper to finish.
The helper is removed when Setup finishes. The finish page lists each client's
verified status and version, the game folder, and Open folder / View setup log
actions. It offers desktop shortcuts and launch in Jump mode only for clients
that pass final verification, including after partial failure or cancellation.
When both clients are ready, choose which one to launch.
Clear an option before Finish to skip it. Existing desktop items named
Q2PRO Race (Jump) or R1Q2 Race (Jump) are left unchanged. Silent setup performs
neither finish-page action and opens no helper window. If changes require a
review, silent setup fails instead of approving them. /CLIENTS=q2pro,
/CLIENTS=r1q2 or /CLIENTS=both sets
the initial client choice; the default remains Q2PRO Race.

Existing custom PAKs, settings, startup scripts and unrelated files are retained.
Process and file-access checks run before each client file is changed. Running
clients or locked managed files stop installation; Starter never closes programs
for you.
The existing-game option shows client files to add or replace and requires
approval before updating them. Different existing client files are backed up
for recovery; identical files can be registered. Rerunning Starter recovers a
verified interrupted client operation before retrying. Cancel during the client
phase requests safe cancellation. Failure leaves the prepared data for retry and
does not report successful setup. A missing Visual C++ x64 runtime is reported
for Q2PRO Race. R1Q2 Race's standalone build does not need that runtime.

Starter retains its four data/ownership files under .starter in fresh folders,
or .q2jump-starter-data in legacy folders. Existing metadata in an owned folder
is preserved across Starter versions. It creates
no uninstaller. Folders with the legacy combined Starter marker
Q2JUMP.installation are not adopted; unrelated uninstallers are kept.
A desktop shortcut created by Starter is not removed automatically;
delete it manually if you later remove the game folder.

This is a local unpublished build. The original data remains subject to its
notices; permission evidence for public redistribution remains unresolved.
